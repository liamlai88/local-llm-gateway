# 实验 #18: 语义缓存降本 —— v1 阈值扫描 + v2 三层架构

> **核心结论**: 单层 embedding 缓存（v1）命中率 28%，远低于业界宣传的 30-50%。
> 加 LLM Normalize + Cross-Encoder Rerank（v2），命中率提升到 40%，且 C 同义改写从 4/10 跃升到 10/10。
> 代价：延迟从 1.4s → 4s。**适合成本敏感非延迟敏感场景**。

## 1. 假设与动机

阿里云海外客户最常问的问题之一是「怎么把 GenAI 成本砍一半」。
教科书答案：语义缓存。但**真实命中率到底多少？**业界宣传的「30-50%命中率」靠谱吗？
本实验做完整的阈值扫描 + 改进方案对照。

## 2. 实验设计

### 2.1 测试集（50 条 query / 5 组）

[experiments/semantic_cache_demo.py](semantic_cache_demo.py):

| 组 | 数量 | 设计意图 |
|---|---|---|
| A. 原始 | 10 | 建立缓存（必 miss） |
| B. 完全重复 | 10 | 验证字面匹配（期望 100%） |
| C. **同义改写** | 10 | **关键测试**："价格"↔"多少钱" |
| D. 相关但不同 | 10 | 同主题不同关注点（不该命中） |
| E. 完全不同 | 10 | 不同主题（必 0 命中） |

### 2.2 v1: 单层 embedding 缓存

[semantic_cache.py](../semantic_cache.py):
```
query → text-embedding-v2 → cosine top-1 → threshold 过滤
```

阈值扫描：0.85 / 0.90 / 0.95 / 0.98

### 2.3 v2: 三层架构（Normalize + Embed + Rerank）

[semantic_cache_v2.py](../semantic_cache_v2.py):
```
query 
  ↓
LLM Normalize 改写为标准形式 ("PRO 套餐的价格是多少呢" → "包月套餐 PRO 价格")
  ↓
Embedding 召回 top-5 (低阈值 0.70)
  ↓
gte-rerank 精排（阈值 0.5）
  ↓
最终命中
```

## 3. v1 阈值扫描结果

| Threshold | 总命中率 | B 重复 | C 同义 | D 相关 | E 无关 | 错误命中 |
|---|---|---|---|---|---|---|
| 0.85 | **28%** | 10/10 | **4/10** | 0/10 | 0/10 | 0 |
| 0.90 | 24% | 10/10 | 2/10 | 0/10 | 0/10 | 0 |
| 0.95 | 20% | 10/10 | 0/10 | 0/10 | 0/10 | 0 |
| 0.98 | 20% | 10/10 | 0/10 | 0/10 | 0/10 | 0 |

**反直觉发现 #1**: text-embedding-v2 对中文同义改写**很挑剔**——阈值 0.95 完全召不回任何改写（包括"包月套餐 PRO 多少钱" vs "PRO 套餐的价格是多少呢"这种语义几乎相同的对）。

业界宣传的 30-50% 命中率？**实测只有 20-28%，且几乎全是字面重复**。

## 4. v1 → v2 改进对照

| 指标 | v1 (th=0.85) | v2 (norm+rerank) | 差值 |
|---|---|---|---|
| 总命中率 | 28% | **40%** | +12pp |
| A 首次提问 | 0/10 | 0/10 | 持平 |
| B 完全重复 | 10/10 | 10/10 | 持平 |
| **C 同义改写** | 4/10 | **10/10** ⭐ | **+6** |
| D 相关但不同 | 0/10 | 0/10 | 持平 |
| E 完全不同 | 0/10 | 0/10 | 持平 |
| 节省 token | 942 | **1286** | +37% |
| 错误命中 | 0 | 0 | **保持 0** ✓ |
| Hit avg 延迟 | 1391ms | **4060ms** | +2669ms |
| Miss avg 延迟 | 3474ms | 5094ms | +1620ms |

**v2 完美命中所有同义改写（C 组 10/10）且零错误命中**。代价是每次 query 多 ~3 秒（normalize + rerank API 调用）。

## 5. 四个核心发现

### 5.1 Rerank score 不是绝对相似度（最大踩坑）

**第一次跑 v2 全部失败（命中率 0%）**，挖出原因是 `gte-rerank` 给**完全相同字符串只评 0.697 分**：

| 字符串对 | gte-rerank score |
|---|---|
| "包月套餐 PRO 价格" vs 自己 | **0.697** |
| "包月套餐 PRO 价格" vs "A100 显存容量" | 0.014 |
| "包月套餐 PRO 价格" vs "退款规则" | 0.016 |

→ **rerank 输出是相对排序，不是绝对相似度**。要看相对差距（0.697 vs 0.016 差 40 倍）而非绝对阈值。把阈值从 0.80 降到 0.5 后 v2 立即工作。

**这种坑只有真做过才知道**——下次面试聊到 rerank，这是个有故事的金句。

### 5.2 LLM Normalize 是关键武器

C 组改写效果：

| 原 query | LLM normalize 输出 |
|---|---|
| "PRO 套餐的价格是多少呢" | "包月套餐 PRO 价格" |
| "ecs.gn7e 上面用的是哪款 GPU?" | "ecs.gn7e GPU 型号" |
| "A100 GPU 内存是多少 GB" | "A100 GPU 内存容量" |
| "客服响应大概多久" | "客服响应时间" |

虚词/语气词被剔除，关键词被保留——**embedding 距离瞬间拉近**。这套方法可以 generalize 到任何 RAG / Cache / 多轮对话场景。

### 5.3 三层架构对 cache 同样有效（呼应 #4 RAG）

| 实验 | 召回层 | 精排层 | 增益 |
|---|---|---|---|
| #4 RAG | Hybrid (Vector+BM25) | gte-rerank | **50% → 100%** |
| **#18B Cache** | Embedding 降阈值 0.70 | gte-rerank ≥0.5 | **28% → 40%** |

> **「召回扩量 + 精排把准」这个范式对 RAG / Cache 双适用**。

### 5.4 业界宣传的命中率不可信

| 来源 | 命中率宣传 | 本实验实测 |
|---|---|---|
| 各厂商语义缓存 SDK 文档 | 30-50% | **20-28% (v1) / 40% (v2)** |
| 月省成本 (10K 次/天 客服) | ¥30-50 | **¥15-23** |

宣传不全是骗，但**测试集偏向字面重复**。真实业务里同义改写的占比决定上限。

## 6. 决策矩阵（适合 P7 面试）

| 场景特征 | 推荐方案 |
|---|---|
| 客户重复问相同问题（FAQ）| v1 即可（0.85 阈值），命中率 ~30% |
| 客户用各种方式问相似问题 | **v2 三层**，命中率 ~40%+ |
| 延迟敏感（< 1s 响应要求）| v1 + 本地化 embedding（ONNX）|
| 成本敏感（百万级 QPS）| v2 + Redis 后端 + 多租户隔离 |
| 高时效性（KB 频繁更新）| 关闭缓存，或加 TTL（5 分钟）|

## 7. 真实经济账

按 **10 万次/天客服场景** 算：

| 方案 | 命中率 | 月节省 LLM 成本 | 额外延迟 |
|---|---|---|---|
| 无缓存 | 0% | ¥0 | 0 |
| v1 baseline | 28% | **~¥800** | +0 |
| v2 三层 | 40% | **~¥1140** | +3s/query |

v2 比 v1 多省 **¥340/月**，但每次 query 多 3 秒等待。

**架构师的取舍**：
- 后台批量任务（用户不等）→ 上 v2，省钱第一
- 实时对话（用户在等）→ 用 v1 + 优化 embedding 本地化（hit < 50ms）

## 8. 工程教训

1. **业界宣传数字 ≠ 你的业务数字**——上线前必须自己跑过
2. **Embedding API 是延迟成本**——hit 不等于 fast，要本地化才能做到 <50ms
3. **Rerank 输出是相对排序，不是相似度**——别用绝对阈值
4. **LLM Normalize 是低估的武器**——一次改写让所有下游受益
5. **三层架构对所有"语义匹配"场景都适用**——不只 RAG

## 11. 一句话总结

> **语义缓存的"语义能力" = embedding 模型 + 改写 + rerank 三者乘积**。
> 单层 embedding 在中文场景命中率只能到 28%（业界宣传 30-50% 是测试集偏置）。
> 加 LLM Normalize + Cross-Encoder Rerank 升到 40%，零错误命中，但延迟翻倍。
> **没有银弹，只有取舍**。
