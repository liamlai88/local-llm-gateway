# 实验 #24: CRAG 的 break-even 点 —— 弱模型上自纠错 RAG 反而更糟

> **核心结论**: #23 发现强模型(qwen-turbo)下 CRAG 冗余。本实验换弱生成器(本地 qwen2.5-1.5B)找 CRAG 的翻盘点。
> 四臂对照（生成器均为 1.5B），6 题（4 可答 + 2 语料没有的 H100/MI300），真实数据**反转了"弱模型上 CRAG 该有用"的假设**：
> **弱模型确实会幻觉（无指令 Naive 安全率仅 0.50），但救它的是一行免费 prompt 弃答指令（→1.00，零额外成本）；
> 而完整 CRAG（弱/强评估器，15–18 调用）安全率全卡 0.50，没救成——强评估器版甚至把"自信的错误上下文"喂给弱模型，安全率反被免费 guard 碾压。**
> 同一弱生成器 + 同一 guard 指令：只加 guard（臂B）弃答成功；guard + CRAG（臂D）却幻觉。**CRAG 的纠错动作主动把安全率做差了。**

## 1. 假设与动机

#23 留下关键变量：CRAG 的价值是否随 base model 变弱而出现? 直觉是"弱模型会幻觉，CRAG 能纠偏"。本实验证伪它。

**待验证假设**:
- H1: 弱生成器(1.5B)在不可答题上会幻觉（失败模式存在）
- H2: CRAG（尤其强评估器）能检测并纠正弱模型的幻觉，安全率 > Naive

## 2. 四臂设计

[crag_weak.py](crag_weak.py)，复用 #23 的语料/检索/测试集/评分，LLM 调用走 `agent.call_llm`（支持 local/bailian）：

| 臂 | 生成器 | 评估器 | 弃答指令 |
|---|---|---|---|
| A Naive 无指令 | 1.5B | — | 无 |
| B Naive +弃答指令 | 1.5B | — | 有 |
| C CRAG 弱评估器 | 1.5B | 1.5B | 有（CRAG 内置）|
| D CRAG 强评估器 | 1.5B | **turbo** | 有 |

## 3. 结果

| 臂 | 可答准确率 | 不可答安全率 | 总调用 |
|---|---|---|---|
| A Naive（无弃答指令） | 0.75 | **0.50** | 6 |
| B Naive（+弃答指令） | 0.75 | **1.00** | 6 |
| C CRAG（弱评估器，全 1.5B） | 0.75 | 0.50 | 18 |
| D CRAG（强评估器，1.5B 生成 + turbo 评估） | 0.75 | 0.50 | 15 |

### ① H1 成立：弱模型确实幻觉

无指令 Naive 对"H100 显存多少?"的输出：
> *"根据资料，'NVIDIA A100 显存 80GB'。所以 H100 的显存是 80GB。"*

弱模型直接**抄了 A100 的规格冒充 H100** —— CRAG 针对的"召回相关项→张冠李戴"失败模式真实存在，安全率掉到 0.50。

### ② 反转点：救它的是免费 prompt 指令，不是 CRAG

- **臂 B（只加一行"没答案必须说信息不足"）安全率 0.50→1.00，零额外调用**。弱模型也能照做弃答。
- **臂 C / D（完整 CRAG，15–18 调用）安全率仍 0.50** —— H2 被否，CRAG 没纠正成。

### ③ 最反直觉：强评估器 CRAG 比免费 guard 更差（CRAG 主动帮倒忙）

臂 D 对 H100 的执行链：
```
turbo 评估器判 INCORRECT → 改写 query → 在同一语料重检（又是 A100 文档）
→ 二次评估判 CORRECT（A100 文档对"GPU 显存"类查询表面相关）
→ 把 A100 文档当"可信上下文"交给弱生成器
→ 1.5B 照着答："根据提供的数据，'NVIDIA A100'的显存为80GB"  ← 幻觉
```
**同一个弱生成器、同一条 guard 指令**：臂 B（无 CRAG）弃答成功，臂 D（有 CRAG）幻觉。
差别就在 CRAG 的"改写+重检"把**语料里根本不存在 H100、却表面相关的 A100 文档**包装成"已纠错、可信"喂了进去，
**制造了虚假置信度**，反而盖过了 prompt guard 本可触发的弃答。

## 4. 为什么 CRAG 在这里救不了（机制层面）

1. **纠错动作无法无中生有**：经典 CRAG 的 INCORRECT 分支靠 **Web 搜索引入新知识**；本离线版只能"同语料改写重检"。
   语料里没有 H100，改写多少次都检不到 → 纠错动作对"信息缺失"型失败**结构性无效**。
2. **重检反而提升错误项的排名与置信**：改写后 A100 文档更靠前，评估器（即便是 turbo）被表面相关性骗判 CORRECT，
   于是给弱生成器递了一份"看起来已验证"的错上下文 —— 比不纠错更危险。
3. **弱生成器是最终瓶颈**：D 的生成仍由 1.5B 完成，前面评估器再强，最后一步把错文档当真照抄。

## 5. 局限

1. **纠错动作被阉割（最大局限）**：没接 Web 搜索。CRAG 真正的杀手锏（引入语料外新知识）没被测到——
   H1/H2 的结论只适用于"同语料改写"型 CRAG。**接 Web 搜索后 CRAG 很可能在不可答题上真正翻盘**，这是下一步。
2. **可答准确率全卡 0.75**：4 臂都错在"最便宜实例"那题（弱模型比较推理错，把 gn7e 当成最便宜）——这是弱模型的推理天花板，与 CRAG 无关；D 还在该题过度弃答（"信息不足"），是强评估器导致的过度保守。
3. n=6、单弱模型、明显域外查询，不下统计结论（对齐 #19）。

## 6. 结论与生产指引

1. **最廉价的杠杆在两个模型档位都占优**：一行弃答指令 → 强模型(#23)和弱模型(#24)安全率都到 1.00，零额外成本。
2. **CRAG 的"同语料纠错"对信息缺失型幻觉结构性无效，还可能帮倒忙**（制造虚假置信度）。它要值钱必须满足：
   纠错动作能**引入新知识（Web/外部源）**，否则不如一行 prompt 指令。
3. **评估器强 ≠ 系统安全**：D 评估器是 turbo 仍 0.50，因为最终生成由弱模型完成、且纠错喂了错上下文。**安全性由最弱环节 + 上下文质量共同决定，不是堆评估器能力。**
4. **方法论再次验证（接 #23）**：必须单列"最廉价那一臂（prompt guard）"。否则会把"防幻觉"的功劳误记给 CRAG，
   而真相是 CRAG 不仅没立功，强评估器版还落后于免费 guard。

## 7. 与既有实验的关系：负面发现"四连"的统一规律

#12 Reflection / #22 Ontology / #23 CRAG / #24 CRAG-弱模型，统一规律浮现：
> **复杂增强机制（Reflection / Ontology / CRAG）能否兑现收益，取决于"它纠正的环节"是否真是当前系统的绑定约束。**
> - base model 已能 grounding → CRAG 冗余（#23）
> - 失败可被一行 prompt 修复 → CRAG 不如 guard（#24）
> - 纠错动作不能引入新知识 → CRAG 对信息缺失无效（#24）
>
> **先定位绑定约束，再决定加不加机制** —— 这比"默认上最潮的 RAG 范式"更重要。
