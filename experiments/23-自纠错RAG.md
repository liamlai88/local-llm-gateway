# 实验 #23: 自纠错 RAG（CRAG, Corrective RAG）—— 机制冗余的边界

> **核心结论**: 给 RAG 加「检索质量评估器 + 纠错动作（query 改写 / 知识精炼 / 弃答）」。
> 三臂对照（Naive 无弃答指令 / Naive 有弃答指令 / CRAG），6 题含 4 可答 + 2 语料里根本没有的不可答题（H100、MI300）。
> 真实数据：**三臂可答准确率、不可答安全率全部 1.00 = 1.00 = 1.00，但 CRAG 烧了 2.5x 调用（15 vs 6）。**
> 最反直觉的一点：**连完全没有弃答指令的朴素 RAG 都没幻觉**——qwen-turbo 自己就答"资料中未提及 H100"。
> **CRAG 想解决的「召回差→幻觉」失败模式，已被现代强模型的 grounding 能力免费兜住**，那套评估+纠错机器在这组上纯属冗余成本。

## 1. 假设与动机

CRAG 的卖点：朴素 RAG 召回不好也硬塞进去生成 → 幻觉。加一个评估器判召回好坏，差则纠错（改写重检/弃答）。
**待验证假设**:
- H1: 在"语料里没有答案"的不可答题上，朴素 RAG 会幻觉，CRAG 能检测并弃答（CRAG 安全率 > Naive）
- H2: CRAG 的纠错成本（多次 LLM 调用）能换来可测收益

## 2. 系统设计

[crag_rag.py](crag_rag.py)，复用 graphrag.call_llm + 轻量内存向量检索（百炼 embedding + cosine）：

```
query → 检索 top-k → 评估器(CORRECT / AMBIGUOUS / INCORRECT)
  ├ CORRECT   → 直接生成
  ├ AMBIGUOUS → 知识精炼(句子级 strip 过滤去噪) → 生成
  └ INCORRECT → query 改写 + 重检索；二次评估仍 INCORRECT → 弃答"信息不足"
```

**三臂对照**（关键：第三臂是为了堵"baseline 被喂强"的方法论漏洞）：

| 臂 | 说明 |
|---|---|
| Naive（无弃答指令） | 最朴素，answer prompt 不含任何"没答案就弃答"约束 → 暴露真实幻觉行为 |
| Naive（+弃答指令） | answer prompt 加一行"没答案必须说信息不足，禁止编造" |
| CRAG | 完整评估器 + 纠错动作 |

语料 = #13 KB + 2 条干扰，**故意不含 H100 / MI300**。

## 3. 结果

| 系统 | 可答准确率 | 不可答安全率 | 总 LLM 调用 |
|---|---|---|---|
| Naive（无弃答指令） | 1.00 | **1.00** | 6 |
| Naive（+弃答指令） | 1.00 | 1.00 | 6 |
| **CRAG** | 1.00 | 1.00 | **15** |

度量口径：可答题=答案含正确关键词；不可答题=弃答(含"未提及/信息不足"等)且不吐造假规格数字为"安全"。

### 关键观察

**① H1 被否：朴素 RAG 根本没幻觉（连无弃答指令版都没有）**
不可答题上，无指令 Naive 的实际输出：
- "H100 的显存是多少 GB?" → *"答案：资料中未提及 H100 的显存信息。"*
- "支持 AMD MI300 吗?" → *"目前资料中未提及支持 AMD MI300 加速卡，仅提到支持 NVIDIA..."*

**模型自己就拒绝了幻觉。** qwen-turbo 这类现代指令模型已被训练得对"给定 context 忠实"，context 里没有就说没有——
CRAG 评估器想替它做的"判断召回不相关"，模型在生成阶段已经隐式做了。

**② H2 被否：CRAG 多烧 2.5x 调用换来 0 可测收益**
三臂安全率/准确率完全一致 1.00，CRAG 却要 15 次调用（每条可答题 2 次、不可答题 3–4 次）。
评估器 + 改写 + 二次评估这套机器，在这组语料+这个模型上**纯属冗余成本**。

**③ CRAG 的路由是对的，只是没用武之地**
CRAG 的判断本身没错：4 道可答题全判 `CORRECT→direct`，2 道不可答题判 `INCORRECT→改写/弃答`——
路由 6/6 正确。问题不在 CRAG 判错，而在**它正确判断后触发的纠错，模型本来就会做**。

## 4. 诚实的局限（这才是结论的边界）

这个"CRAG 无用"的结论**强烈依赖两个条件**，换条件可能翻转：

1. **不可答题"太明显"**：H100/MI300 与语料是清晰的域外，模型一眼看穿。
   CRAG 真正的主场是**"长得像但其实错"的微妙召回失败**（检索到高度相关但答非所问的文档），本测试集没覆盖。
2. **生成器是强模型（qwen-turbo）**：grounding 能力强。**换成弱模型（本地 1.5B）很可能真幻觉**，
   那时 CRAG 的评估器才有价值。本实验没测弱模型臂——这是 CRAG 能否"翻盘"的关键变量。
3. **纠错动作被阉割**：经典 CRAG 的 INCORRECT 分支是**触发 Web 搜索引入新知识**；
   离线版只能"在同一语料里改写重检"，无法找回语料里根本不存在的信息。CRAG 注入新知识的核心能力没被测到。
4. 样本量小（n=6）、单模型，不下统计结论（对齐 #19）。

## 5. 结论与生产指引

1. **现代强模型 + 明显域外查询：CRAG 冗余**。base-model 的 grounding 已免费兜住"召回差→幻觉"，
   2.5x 成本买不到收益。一行弃答指令(甚至什么都不加)就够。
2. **CRAG 的价值随 base model 变强而衰减**：它针对的是 2023 era 模型的幻觉，2025 era 模型已大幅自愈。
3. **CRAG 真正值得上的场景**（本实验反推）：
   - 弱模型/小模型部署（会幻觉，需外部评估器纠偏）
   - 微妙召回失败（相关但错的文档，模型自己看不穿）
   - 纠错动作能**引入新知识**（Web 搜索），而非同语料改写
4. **方法论自省**：第三臂（无弃答指令）是关键——没有它，会误以为是"+弃答指令"或 CRAG 立的功，
   实际是 base model 立的功。**做对照一定要把"免费的廉价杠杆"单列一臂**，否则会把功劳记错给复杂方案。

## 6. 与既有实验的关系（负面发现三连）

- 与 **#12（Reflection 修不了事实错）/ #22（本体治好图但准确率不动）** 构成"机制冗余/边界"三连：
  **复杂机制（Reflection / Ontology / CRAG）的收益，强烈依赖 base model 的短板是否真的在那个机制能补的地方**。
  base model 越强，这些 2023-era 增强机制的边际收益越小。
- 这正是 P7 SA 最该有的判断力：**不是堆最潮的 RAG 范式，而是先测 base model 的失败模式到底在哪**，再决定加不加。

**面试金句（P7 SA，"客户问要不要上 CRAG/Self-RAG"）**:
> "我会先反问:你的 base model 多强、失败模式到底是什么。我实测过 CRAG——在 qwen-turbo 上加了检索评估器和纠错回路，结果三臂对照(含一个完全不加防幻觉指令的朴素 RAG)安全率全是 100%，CRAG 还多烧了 2.5 倍调用。因为现代模型的 grounding 已经强到 context 里没有就说没有，不需要外挂纠错。
