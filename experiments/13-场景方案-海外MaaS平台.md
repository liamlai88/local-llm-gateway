## 2. 三类目标客户

### A. 中小企业 & 创业公司（量大、价格敏感）

**痛点**：想用 AI 但不想自建 GPU 集群，需要快速验证产品
**诉求**：按量付费、低起步成本、OpenAI 兼容 API（代码迁移成本低）
**典型场景**：东南亚 SaaS 创业公司接入 LLM 做客服机器人

### B. 互联网企业（技术强、流量大）

**痛点**：自有模型成本高、多模型选型复杂、需要 SLA 保障
**诉求**：高并发、低延迟、模型路由、A/B 测试、Prefix Caching 降成本
**典型场景**：电商平台用 AI 做商品描述生成，日调用量 100 万次

### C. 大型企业 & 政企（预算大、合规严）

**痛点**：数据不能出境、需要私有化部署、要求与现有系统集成
**诉求**：专有集群、数据隔离、SLA 99.9%、本地化合规
**典型场景**：印尼国有银行部署内部知识库问答，数据主权要求高

## 3. 技术架构：六层 MaaS 平台（2026 参考架构）

```
客户请求
    │
    ▼
┌─────────────────────────────────────────┐
│  层1：接入层（API Gateway）              │
│  认证（API Key）/ 限流 / 请求路由        │
│  OpenAI 兼容接口，客户代码零改动         │
│  → 对应代码：gateway.py                 │
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│  层2：模型路由层（Model Cascade）        │
│  简单请求 → 小模型（低延迟低成本）       │
│  复杂请求 → 大模型（高准确率）           │
│  降级兜底：云端失败 → 本地 fallback      │
│  → 对应代码：gateway.py 路由逻辑        │
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│  层3：缓存层（Prefix Cache + 响应缓存）  │  ← 2026 新增
│  Prefix Caching：重复系统 prompt 节省   │
│  80% 输入 token 成本                    │
│  响应缓存：完全相同请求命中率 ~20%       │
│  → 对应代码：gateway.py response_cache  │
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│  层4：推理层（Hybrid Inference）         │
│  本地：Ollama / vLLM（Qwen2.5 1.5B-7B）│
│  云端：百炼（Qwen3-Max / Turbo / Wan2.5）│
│  生产推理引擎：vLLM（PagedAttention）   │  ← 2026 标准
│  量化：FP8/INT4，显存减半，速度翻倍     │
│  → 对应代码：Ollama + 百炼 API          │
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│  层5：计量计费层（Metering）             │
│  按 API Key + 模型分别统计 token 用量    │
│  输入 / 输出 / 缓存命中 分开计价         │
│  批量推理（Batch）享 50% 折扣           │
│  → 对应代码：Prometheus metrics         │
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│  层6：管理控制台                         │
│  实时用量 / 成本 / 延迟 / 错误率看板     │
│  多模型 A/B 测试管理                    │
│  → 对应代码：Grafana Dashboard          │
└─────────────────────────────────────────┘
```

### 2026 生产推理优化（面试加分点）

| 技术 | 原理 | 效果 |
|---|---|---|
| **Prefix Caching** | 相同系统 prompt 的 KV 矩阵只算一次，后续请求复用 | 输入 token 成本降 80%（Qwen3 实测）|
| **Prefill-Decode 分离** | 输入处理（compute-bound）和输出生成（memory-bound）独立扩容 | GPU 利用率提升 30-40% |
| **Continuous Batching** | 请求完成即出队，新请求即入队，不等整批结束 | 吞吐量提升 2-3x |
| **FP8 量化** | 从 FP16 → FP8，显存减半，精度损失 <1% | 同显存跑 2x 规模模型 |
| **PagedAttention (vLLM)** | KV 缓存分页管理，消除显存碎片 | 并发请求数提升 3-4x |

> **Demo 说明**：本地用 Ollama（MacBook M5 开发验证），生产环境替换为 vLLM + 阿里云 GPU 集群，接口层 gateway.py 不变。

### 模型路由策略（Model Cascade）

```
请求分类
    │
    ├─ 简单（FAQ / 关键词匹配）
    │      → Qwen2.5-1.5B 本地（<100ms，¥0）
    │
    ├─ 中等（多轮对话 / 摘要）
    │      → Qwen2.5-7B 本地（<500ms，¥0）
    │
    ├─ 复杂（专业推理 / 代码 / 高准确率）
    │      → Qwen3-Max 云端（<2s，$0.78/M tokens）
    │
    └─ 多模态（图片/视频理解）
           → Wan 2.5 云端（视觉任务专用）
```

## 5. TCO 模型（2026 真实定价重算）

### 场景假设：互联网企业，日调用 100 万次，均值 500 tokens（300 输入 + 200 输出）

月 Token 用量：
- 输入：100万次 × 300tokens × 30天 = **90亿 tokens（9,000M）**
- 输出：100万次 × 200tokens × 30天 = **60亿 tokens（6,000M）**

| 方案 | 月成本估算 | 计算说明 |
|---|---|---|
| 全量 GPT-5.5 | **¥162 万/月** | $5×9,000M + $30×6,000M = $225,000 |
| 全量 Claude Haiku 4.5 (Bedrock) | **¥28 万/月** | $1×9,000M + $5×6,000M = $39,000 |
| 全量 Qwen-Turbo | **¥7,750/月** | $0.033×9,000M + $0.13×6,000M = $1,077 |
| Qwen3-Max + Prefix Caching | **¥3,400/月** | 40% 缓存命中，实际输入成本降 50% |
| **ai-gateway Model Cascade** | **¥2.3 万/月** | 70%本地¥0 + 30%Turbo ¥2,326 + 服务器¥2万 |
| 自建 GPU（3x A10，含运维）| **¥6 万/月** | 硬件¥29,400 + 运维人力¥3万 |

### 关键洞察

1. **云端 MaaS vs 竞品**：Qwen-Turbo 比 GPT-5.5 便宜 **209 倍**，比 Claude Haiku 便宜 **36 倍**
2. **Prefix Caching 的价值**：系统 prompt 重复率高（如客服场景 >80%），Qwen3-Max 成本可再降 50%
3. **Hybrid vs 纯云端**：Model Cascade 的价值在于**延迟**（本地 <100ms vs 云端 ~500ms）和**可用性**（云端故障本地兜底），而非单纯成本

### 从 GPT-5.5 迁移到百炼的年化节省

|---|---|
| GPT-5.5 → Qwen-Turbo | **¥1,940 万/年** |

## 6. 实施路线图

### PoC 阶段（第 1-2 周）
- 目标：验证 API 兼容性，OpenAI SDK 改一行 base_url 即接入
- 交付物：接入 Demo + 延迟/成本对比报告
- 成功标准：延迟达标（P99 < 2s），成本 < 现有方案 50%

### 试点阶段（第 3-8 周）
- 目标：10% 流量灰度，开启 Prefix Caching，验证实际成本降幅
- 成功标准：
  - 缓存命中率 > 30%
  - 本地模型承接率 > 60%（Model Cascade 方案）
  - P99 延迟 < 2s
  - 月账单降幅 > 70% vs 原方案

### 生产阶段（第 9-16 周）
- 目标：全量切换，本地推理引擎从 Ollama 升级为 vLLM（生产级）
- SLA：99.9% 可用性，P99 < 2s
- 运维：阿里云负责平台层，客户负责 prompt 优化和模型选型

## 7. 风险与合规

| 风险 | 应对方案 |
|---|---|
| **模型幻觉影响业务** | 高风险场景（金融/医疗）强制走 Qwen3-Max + 人工审核，不走小模型 |
| **云端 API 抖动** | 本地 vLLM 作为 fallback，Circuit Breaker 自动切换，P99 超阈值告警 |
| **数据主权** | 政企客户走专属集群，敏感数据走本地推理层，不经共享推理池 |
| **成本超支** | 每 API Key 设 token 用量上限，超限自动限流；月度成本告警 |
| **模型版本升级** | gateway 路由层统一管理，客户代码零改动，模型升级对业务透明 |
| **Prefix Cache 失效** | 系统 prompt 变更时主动清空缓存；监控缓存命中率，低于 20% 告警 |

## 8. 方案亮点总结（面试用）

1. **五层架构全部有代码对应**：gateway.py + Prometheus + Grafana，非 PPT
2. **2026 真实定价支撑**：Qwen-Turbo 比 GPT-5.5 便宜 150 倍，有据可查
3. **Prefix Caching 是 2026 新杀手锏**：客服/RAG 场景缓存命中率 >40%，成本再降 50%
4. **Model Cascade 价值重定位**：成本优化是次要，主要价值是延迟 + 可用性
5. **中企出海一站式**：200+ 模型、国内外同 SDK、Wan 2.5 多模态，一个平台全覆盖
