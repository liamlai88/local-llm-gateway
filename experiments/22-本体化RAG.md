# 实验 #22: 本体化 RAG（Ontology-grounded RAG）—— 能否抬高 #13 的天花板

> **核心结论**: 在 #13 的 GraphRAG 上加一层**从"业务访谈"提炼的领域本体（实体类型 + 受控关系词表 + 实体归一规则）**约束抽取。
> 真实数据呈现一个精确的「分裂」结果：**本体把图质量彻底治好了——实体碎片 8→0、非法关系边 8→0、节点 31→19(−39%)，
> 但多跳问答准确率纹丝不动：0.8 = 0.8。**
> 原因经查证清晰：① 自由抽取的图确有 #13 所述病理（碎片节点物理切断多跳路径、层级被编码成文本节点而非边）；
> ② 但在 10 篇文档的小 KB 上，**强生成器(qwen-turbo)能从 2-hop 子图的原文里把碎片重新缝合**，掩盖了结构缺陷。
> **修正 #13 的认知：抽取质量是图"卫生"的天花板，但在小 KB 上它不是问答准确率的"绑定约束"**——本体的结构收益要在大规模图上才会变成决定性优势。

## 1. 假设与动机

#13 的负面结论：GraphRAG 多跳准确率 < Naive RAG，病根是"自由抽三元组"质量差。
**本体化 RAG 是针对这个病根的标准修法**：先做知识工程（业务访谈）提炼 schema，让 LLM 只能按 schema 抽取。

**待验证假设**:
- H1: 本体约束能显著降低实体碎片化和关系类型噪声（图质量提升）
- H2: 图质量提升能转化为多跳问答准确率提升（抬高 #13 天花板）

## 2. 领域本体（业务访谈产物）

[ontology_rag.py](ontology_rag.py)，复用 #13 的 graphrag.py（build/query/naive 不动，只换抽取器）：

```
实体类型: 套餐 / 实例 / GPU / 人员 / 规格值
受控关系词表(只能用这 9 种，括号是允许连接的类型):
  包含(套餐→实例) 总价(套餐→规格值) 使用(实例→GPU)
  按量价格/包月价格(实例→规格值) 显存/算力(GPU→规格值)
  下属(人员→人员) 负责(人员→实例)
实体归一: A100/NVIDIA A100/A100 GPU → "NVIDIA A100"；ecs.gn7e 全称 → "ecs.gn7e 实例" ...
```

两臂对照：`free` = #13 原样自由抽取；`ontology` = 上述 schema 约束 + 归一。测试集与 #13 **完全一致**（5 道多跳题）。

## 3. 结果

| 指标 | 自由抽取 | 本体约束 | 解读 |
|---|---|---|---|
| 节点数 | 31 | **19** | 归一后更紧凑(−39%) |
| 边数 | 24 | 20 | 噪声边被拒 |
| 关系类型数 | 9 | 9 | 数字巧合，但内容不同（见下）|
| **实体碎片数** | **8** | **0** | 本体完美归一 |
| **非法关系边** | **8** | **0** | 关系全部受控 |
| 多跳准确率 | 0.8 | 0.8 | **没动** |

### ① 图质量：本体大获全胜（H1 成立）

自由抽取的关系词表是 `['使用','包含','包月','总价','按量付费','是','显存','算力','负责']`——
其中 **`是`** 是个垃圾关系，制造了 8 条非法边，把层级信息编码成了文本节点：

```
自由抽取(病理):
  李四 ──[是]──> "张三的下属"     ← "张三的下属"成了一个文本节点，不是 张三→李四 的边！
  王五 ──[是]──> "李四的下属"     ← 下属链断成孤立文本，无法图遍历
  ecs.gn7e 实例 ──[使用]──> "NVIDIA A100 GPU"
  "NVIDIA A100" ──[显存]──> 80GB   ← 注意：A100 碎成两个节点！
                                     使用边指向"A100 GPU"，显存边从"A100"出发
                                     → 实例→GPU→显存 这条 2 跳路径在 GPU 处物理断裂

本体约束(治愈):
  关系词表 ['下属','使用','包含','包月价格','总价','按量价格','显存','算力','负责']
  张三 ──[下属]──> 李四 ──[下属]──> 王五   ← 层级是真边，可遍历
  ecs.gn7e 实例 ──[使用]──> NVIDIA A100 ──[显存]──> 80GB  ← A100 单节点，路径贯通
```

碎片明细对照（每个核心概念被拆成几个节点，理想=1）：

| 概念 | 自由抽取 | 本体 |
|---|---|---|
| A10 | **4** | 1 |
| A100 / gn7e / gn7i / 张三 / 李四 | 各 2 | 各 1 |

**本体把"实体碎片化"这个 #13 病根从 8 降到 0** —— 这正是它该干的事，且确实干成了。

### ② 但准确率没动：0.8 = 0.8（H2 不成立，本 KB 上）

图都治好了，多跳准确率为什么不涨? 逐题查证：

- **强生成器掩盖结构缺陷**：GraphRAG 检索是把 2-hop 子图的**三元组原文**拼进 prompt。
  在 10 篇文档的小 KB 上，碎片节点（`NVIDIA A100 GPU` 和 `NVIDIA A100`）常常同时落在 2-hop 邻域里，
  qwen-turbo 凭字符串相似度就在 prompt 里把它们**重新缝合**了 —— 结构断裂被语言模型在生成阶段补偿掉。
- **剩余的错是推理错/评分噪声，不是图质量错**：
  - 自由抽取那道"过"的 Q4，答案其实**事实错误**（说"李四的上级是王五"，王五实为李四下属），
    只因蒙到关键词 `ecs.gn7e` 被判对 —— **关键词评分给错误答案送了分**。
  - 本体那道"错"的 Q4，推理其实**更正确**（"李四的上级是张三，张三不直接负责实例"），却因没吐出关键词被判错。
  - 两边的失败都源于**生成/遍历推理 + 评分粒度**，与图是否干净无关。

## 4. 诚实的局限与边界

1. **KB 太小（10 文档）是本实验的根本局限**：碎片之所以没伤准确率，正因为 2-hop 邻域小到能把碎片一起捞进 context。
   **本体的结构收益要在大规模/高噪声语料上才会显现**——当图大到必须依赖结构本身做检索（而非让 LLM 重读全部原文）时，
   碎片切断路径就会直接变成召回失败。本 KB 无法暴露这一点。
2. **样本量小（n=5）+ 关键词评分粗**：Q4 暴露了评分会给"事实错但含关键词"的答案送分。
   要严谨需换 LLM-as-judge（#19）或事实核对，并扩大题量。
3. **本体是手工的**：9 种关系、归一表都是人工定义。换域要重做访谈——这是本体化的固有成本。

## 5. 结论与生产指引

1. **本体确实治好了图质量**（碎片 8→0、非法边 8→0、节点 −39%），H1 铁证；这是可复现的强结论。
2. **图质量 ≠ 问答准确率（在小 KB 上）**：强 LLM 生成器会补偿结构缺陷，使本体的好处在小规模下"隐形"。
   **修正 #13**：抽取质量是图卫生的天花板，但不是小 KB 问答准确率的绑定约束；后者卡在推理 + 评测。
3. **何时上本体化 RAG**（真正的适用边界）：
   - ✅ 大规模/高噪声语料、强结构领域（金融风控/医疗/供应链）——碎片会真的切断路径，本体收益决定性
   - ✅ 需要可解释多跳回溯（顺着真边讲"为什么"）
   - ❌ 小 KB / 单段就能答 / 开放域 —— 本体的人工成本换不回收益（呼应 #13：这种场景 Naive RAG 反而赢）
4. **天花板转移而非消失**（#13/#08 一贯结论）：本体把"LLM 抽取质量"的天花板换成了"人工本体 + 访谈质量"的天花板。

## 6. 与既有实验的关系

- 直接续 **#13**：#13 诊断"抽取质量是天花板"，#22 给出标准药方并**实测其边界**——药对症（图质量），但在小 KB 上没治到"病症"（准确率），因为真正的绑定约束换了位置。
- 复用 **#04** 思路：本体化的下一步可叠加 rerank 做子图精排。
- 知识工程视角接 **SA 岗位**：本体 = 把客户领域知识结构化，这步本身就是解决方案岗的核心动作。
