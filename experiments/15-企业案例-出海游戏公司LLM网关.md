## 2. 4 大 AI 场景识别

把客户 4 个痛点对应到 4 个 AI 场景，**每个场景的 SLA / 调用量 / 选型完全不同**——这是这个项目最重要的认知。

| 场景 | QPS | 延迟 SLA | 调用方式 | 优先级 |
|---|---|---|---|---|
| **AI NPC 对话** | 5,000 峰值 | P99 < 1s | 同步 + 流式 | 🔴 P0 |
| **聊天/公会名审核** | 2,000 峰值 | P99 < 500ms | 同步 | 🔴 P0 |
| **AI 客服问答** | 50 峰值 | P99 < 3s | 同步 | 🟡 P1 |
| **本地化批量翻译** | 离线 | 批处理 < 4h | 异步 | 🟡 P1 |

**SA 关键判断**：
> "游戏 AI 不是一个延迟需求，是**至少 4 种延迟需求**——把它们放到同一个网关下统一治理，但**用不同的路由策略和模型**。"

### 3.2 数据流（AI NPC 对话为例）

```
玩家发话 ("帮我找下任务点")
   │ (1) WebSocket → 阿里云全球加速
   ▼
[Edge Gateway 新加坡节点]
   │ (2) JWT 认证 + QPS 检查
   ▼
[Layer 4-2 语义缓存]
   │ (3) 查相似问题（命中率 35%）
   │      命中 → 直接返回（10ms）
   │      未命中 ↓
   ▼
[Layer 4-1 智能路由]
   │ (4) 判断对话复杂度
   │     简单(70%) → 本地 7B
   │     复杂(30%) → 百炼 Turbo
   ▼
[Layer 4-3 玩家上下文]
   │ (5) 拉 Redis 最近 5 轮对话 + ChromaDB NPC 长期记忆
   ▼
[Layer 3-1 本地 vLLM 推理]
   │ (6) 拼 prompt + 流式生成
   │     首 token < 300ms
   ▼
[Layer 4-4 输出审核]
   │ (7) 黑名单 + 政治敏感词过滤
   ▼
返回玩家（首字符 500ms，全文 1.5s）
```

## 5. 关键技术细节（深挖 4 个）

### 5.1 AI NPC 的"人格一致性"问题

**痛点**：NPC 张三在第 1 章说自己讨厌喝酒，第 5 章玩家请客时回答"好啊我最爱喝酒"——人设崩塌。

**根因**：纯 prompt 工程做不到，因为单次对话 context 装不下 NPC 全部历史。

**方案**：**RAG + Memory 双层架构**

```
NPC "张三" 的记忆系统:
├── 静态人格库 (RAG 知识库)
│   · 出身/性格/口头禅/亲属关系/价值观（500条事实）
│   · 由游戏策划在编辑器里维护
└── 动态记忆 (ChromaDB)
    · 与玩家 X 的历史对话（自动入库）
    · 关键事件标记（"答应过玩家 X 帮忙找剑"）
    · 衰减策略：30 天未触发的记忆降权
```

**每次对话**：
1. 检索 NPC 张三的静态人格（top-10 事实）
2. 检索张三与当前玩家的 top-5 历史互动
3. 拼接到 system prompt，再让 LLM 回答

**实测**：人格一致性测试集 100 题，纯 prompt = 62 分，RAG+Memory = 89 分。

### 5.2 语义缓存——降本核心

游戏里 NPC 问题高度重复：
- "你好" / "Hello" / "Hi 张三" — 同一类问题
- "我的任务在哪" / "下个任务点" / "Where is my quest" — 同一意图

**做法**：
1. 玩家输入 → Embedding（text-embedding-v2，1536 维）
2. ChromaDB 余弦相似度搜索
3. 阈值 > 0.92 → 命中缓存，直接返回
4. 命中率实测 **35%**

**成本影响**：
- 不开缓存：5000 QPS × 86400s × 30 天 × 200 tokens × ¥0.03/M = ¥75 万/月
- 开缓存：65% × ¥75 万 = ¥49 万/月
- **每月省 ¥26 万**

### 5.3 多语言聊天审核（最复杂的一环）

**挑战**：5 国语言（印尼/越南/泰国/阿拉伯/韩语）+ 方言 + 火星文绕过

**架构**：
```
聊天消息
   ↓
[BM25 黑名单] (50ms)
   - 已知违禁词命中 → 拒绝
   - 模糊词进入下一层
   ↓
[语言识别] (20ms)
   - fasttext lang-id
   ↓
[百炼内容安全 API] (200ms)
   - 多语言违禁内容检测
   - 高置信(>0.9) → 自动判定
   ↓
[本地 LLM 上下文判断] (500ms)
   - 模糊场景：辱骂 vs 调侃
   - Qwen2.5-7B + 游戏黑话词典 RAG
   ↓
[人工复审队列] (申诉)
```

**关键创新**：**游戏黑话词典 RAG**——把"挂、外挂、G、玻璃心、傻 X(空格变体)"等游戏圈违禁词单独建库，**误判率从 18%（通用模型）降到 4%**。

### 5.4 本地化翻译——出海最痛

**老流程（6 周）**：
1. 策划写中文 → 翻译公司报价 → 译稿回收 → QA 校对 → 嵌入资源 → 测试

**新流程（5 天）**：
1. 策划在 CMS 标记"待翻译"
2. **Qwen-MT + 游戏术语库 RAG**自动批量翻译
3. 本地 7B 模型做风格统一（保持 NPC 语气）
4. 翻译公司**只校对**而非翻译，工作量降 80%
5. CI/CD 自动嵌入资源 + 出包

**成果**：
- 单次本地化成本：¥30 万 → ¥6 万（-80%）
- 周期：6 周 → 5 天
- 8 国语言一次完成

| 风险 | 触发条件 | 应对方案 |
|---|---|---|
| **NPC 输出不可控** | 模型说脏话 / 透露剧情 spoiler | 4 道防线：审核 prompt + 输出过滤 + RAG 知识边界 + 玩家举报闭环 |

## 9. 🎯 项目经验总结（面试讲故事的核心）

### 9.1 5 条可复用的 SA 方法论

**1. "AI 不是一个延迟需求，是多个延迟需求"**
> 游戏里 NPC（<1s）、审核（<500ms）、客服（<3s）、翻译（离线）需求完全不同。**SA 第一件事是分场景做 SLA 矩阵**，再分别选型，**不要试图用一个统一架构解决所有问题**。

**2. "本地 + 云端混合是 ROI 最高的方案"**
> 90% 流量本地 GPU 解决成本和延迟问题，10% 流量云端解决弹性和长尾问题。**纯本地浪费弹性，纯云端浪费成本**。

**3. "客户最初的需求往往是错的"**
> 客户要买 A100，我说服换 A10，省 ¥210 万；客户要做"超大模型 NPC"，我建议做"小模型 + RAG 人格"，省 90% 推理成本同时效果更好。**SA 的价值是帮客户做更好的选择，不是满足错误的需求**。

**4. "A/B 测试是 AI 落地的必经之路"**
> AI 上线**必须配对照组**，不然客户老板永远问你"提升从哪来的"。我们在试点阶段强制做了 A/B，**结果不仅证明了价值，还反向找到了 3 个需要优化的场景**。

**5. "运维交接比技术方案更重要"**
> 客户 SRE 团队接不住 LLM 系统是 90% 案例失败的原因。我们配套设计了**托管运维包 + 3 个月伴飞**——这部分是阿里云的服务收入，也是客户成功的保障。
